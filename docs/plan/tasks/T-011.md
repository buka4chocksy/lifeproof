- **Task:** T-011 — Walking skeleton: workspace dashboard UI

## Objective

Build the walking-skeleton UI so a user can create a workspace and see it: a create-workspace form and
an empty-state category dashboard, wired to the frozen API contract, with the new design tokens mirrored
and the hardcoded brand externalized. This proves "create a workspace → see it in the UI" end to end.

## Acceptance (testable)

1. **Dev auth.** The client sends `X-Dev-User-Id` on every API call, sourced from a single dev constant
   (synthetic UUID, e.g. `11111111-1111-4111-8111-111111111111`) or `NEXT_PUBLIC_DEV_USER_ID` if set.
   `X-Request-Id` is generated per request (`crypto.randomUUID()`); `Idempotency-Key` is sent on `POST`.
2. **Create workspace** (`/workspaces/new`): a form with `name` (text, required, 1–200), `type`
   (`family`/`personal`; `business` hidden in Phase 1), `region` (`GB` default selected; `NG` disabled with
   a "coming later" hint). Plain-language security note (no "zero-knowledge" claim). Submit → `POST
   /workspaces`; on `201` navigate to `/workspaces/{id}?created=1`. Field-level `422` errors and
   `409 workspace.name_conflict` surfaces inline; `401`/`403`/`5xx` show a calm error + retry.
3. **Dashboard** (`/workspaces/[id]`): fetch `GET /workspaces/{id}`; render the workspace name header and
   the 11-category empty-state scaffold (Documents, Banking, Insurance, Property, Investments, Pension,
   Tax, Business, Subscriptions, Crypto, Custom — each card has one primary "Add" action that reveals a
   calm "available in the next milestone" note, not a dead end). When `?created=1`, show a non-alarming
   confirmation ("Your safe is ready" + "recorded in your audit log"). `404`/`401`/`5xx` show error states.
4. **Tokens + brand.** Mirror `--danger`/`--danger-soft`/`--line-strong` into `globals.css` and add
   `danger`/`danger-soft`/`line-strong` to `tailwind.config.ts`. Replace every hardcoded `LifeProof`
   string (header, heading, body, `aria-label`, and `layout.tsx` `metadata.title`) with the
   `brand.name` token from `@lifeproof/design-tokens` (it is an empty placeholder until M5 — that is
   correct, do not invent a name).
5. **Accessibility** (WCAG 2.2 AA for this flow): every field/button has a programmatic name; visible
   focus; keyboard-only completion; 360 px single-column; `≥44px` touch targets; reduced-motion respected.
   No blank screens — every screen has loading/empty/error/success states.
