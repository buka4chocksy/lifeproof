## Acceptance (testable)

1. **RLS** is enabled on `workspaces` and `workspace_members`. Policies scope rows to the tenant via
   `current_setting('app.workspace_id', true)` and, for members, also allow the authenticated user's own
   rows via `current_setting('app.current_user_id', true)`. A non-owner role that has not set the
   session variable returns zero rows for another workspace.
2. **`audit_events`** table exists with, at minimum: `id`, `actor_id` (nullable, FK to `users`),
   `action`, `subject_type`, `subject_id`, `request_id`, `ip_hash`, `before_hash`, `after_hash`,
   `prev_hash`, `hash`, `workspace_id`, `created_at`. It is **append-only**: the application role is
   not granted `UPDATE`/`DELETE` on it (enforce with a trigger and/or revoked grants — document your
   choice). Include `prev_hash`/`hash` columns now; full hash-chain computation and daily anchoring is
   a later task (US-141).
3. **`workspaces.region`** defaults to `'GB'`; `'NG'` remains a valid value. Document that Nigeria has
   no build work yet. Do not add a jurisdiction enum that excludes future values.
4. A **new migration** applies cleanly via `pnpm db:migrate` against both an empty database and the
   existing populated dev database (non-destructive, expand-only).
5. **Evidence** (pasted SQL output in your report) proves: (a) cross-tenant read is denied to a
   non-owner role; (b) `INSERT` into `audit_events` succeeds while `UPDATE`/`DELETE` is blocked;
   (c) `INSERT` into `workspaces` omitting `region` lands on `'GB'`.
6. Any seeds added are **synthetic**. No plaintext email, secret, or PII anywhere in schema or seeds.

## Definition of done

- New migration applied; `pnpm typecheck` and `pnpm lint` pass at the repo root (or at least the `db`

- RLS and append-only behavior verified with a non-owner role (SQL output pasted in the report).
- No plaintext secrets in any committed file.
