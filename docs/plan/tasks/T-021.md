# T-021 — Build shared contracts package (resolve D-021)

- **Owner:** backend
- **Status:** done
- **Depends on:** T-006

## Problem

`apps/api` imported `packages/contracts/src/index.ts` by relative path. Because the API compiles with
`rootDir: ./src`, TypeScript failed in dev watch with `TS6059` once the contracts source was pulled into
the program. The wide `rootDir` workaround also emitted a nested `dist/apps/api/src/main.js` path and
left `apps/web` with a duplicated `workspace-types.ts` mirror.

## Change

- `packages/contracts` now builds CommonJS + `.d.ts` to `dist` via `tsconfig.build.json`.
- Package entrypoints are `dist/index.js` / `dist/index.d.ts`.
- `apps/api` imports `@lifeproof/contracts` by package name.
- API `rootDir` reverted to `./src`; Nest `sourceRoot` is `src`; output is `dist/main.js`; start scripts
  updated.
- `apps/web` declares `@lifeproof/contracts` and `workspace-types.ts` is now a type re-export.
- Root `dev`, `typecheck`, and `test` build contracts first. CI builds contracts before the quality gates.
- Added `ApiFieldError` to the shared error contract and exported workspace type aliases.
