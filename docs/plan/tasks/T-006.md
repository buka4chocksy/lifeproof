## Acceptance (testable)

1. **Workspace endpoints** defined under `/v1`, each with `operationId`, request/response schemas, and
   `ErrorEnvelope` error responses:
   - `POST /workspaces` — create (returns `201` + workspace; `400`/`422` on invalid input)
   - `GET /workspaces` — list own workspaces, cursor-paginated (`?cursor=…&limit=…`, max 100)
   - `GET /workspaces/{id}` — get one (`404 workspace.not_found`)
2. **Identity/session model** documented: `Authorization: Bearer` carries an Auth0-issued token whose
   `sub` maps to the internal `users` row; a dev-mode session stub is permitted for the walking
   skeleton but must live behind the identity abstraction, not bypass it. No SMS OTP anywhere.
3. **Workspace schema** matches T-005: `type` (personal/family/business), `name`, `region` (default
   `GB`, `NG` allowed), `status`, `owner_id`, `id`, `created_at`, `updated_at`. Field names match the DB
   contract exactly.
4. **`workspace.created` audit event** specified (event name, `actor_id`, `subject_type=workspace`,
   `subject_id`, `request_id`) so T-010 can emit it. Document that audit writes are append-only and
   content is never returned in the API.
5. **Zod schemas** in `packages/contracts` mirror the OpenAPI workspace, identity, and audit shapes.
   Add Vitest unit tests proving the workspace schema accepts a valid payload and rejects: missing
   `name`, invalid `type`, invalid `region`, non-cursor pagination params.
6. Error codes match Architecture Appendix B (`workspace.not_found`, `auth.forbidden`,
   `rate_limited`, `internal_error`). `401 auth.invalid_credentials`/`403 auth.mfa_required` noted for
   auth failures.
