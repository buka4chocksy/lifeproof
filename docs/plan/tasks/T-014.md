# T-014 — RLS: add list-by-member SELECT policy for workspaces

- **Task:** T-014 — RLS: add list-by-member SELECT policy for workspaces
- **Owner:** dba
- **Depends on:** T-005 (RLS baseline) — unblocks T-010 (backend list endpoint)

## Objective

Close the contract gap found before T-010: `workspaces` has no SELECT policy for "list the caller's
workspaces." Add one, scoped to owner/member, so the API's `GET /workspaces` (and the owner's
`INSERT … RETURNING` during create) work under RLS without cross-tenant leakage.

## Acceptance (testable)

1. New migration `0002_*` adds exactly one policy on `workspaces`:
   ```sql
   CREATE POLICY "workspaces_select_member" ON "workspaces"
     FOR SELECT TO app_user
     USING (
       "owner_id" = current_setting('app.current_user_id', true)::uuid
       OR "id" IN (
         SELECT "workspace_id" FROM "workspace_members"
         WHERE "user_id" = current_setting('app.current_user_id', true)::uuid
       )
     );
   ```
   It must be OR-compatible with the existing `workspaces_select_tenant` (RLS SELECT policies are OR'd,
   so get-one via `id = app.workspace_id` still works).
2. Migration applies cleanly via `pnpm db:migrate` (idempotent re-run) against the populated dev DB.
3. Paste SQL evidence (as `app_user`, with `app.current_user_id` set) proving:
   - **(a)** a user can SELECT the workspace they **own** (`owner_id` match, `app.workspace_id` unset);
   - **(b)** a user can SELECT a workspace they are a **member** of (subquery path);
   - **(c)** a user **cannot** SELECT a workspace they neither own nor belong to (zero rows);
   - **(d)** `INSERT … RETURNING` for a new workspace (owner_id = current user) returns the inserted row
     (the owner-based policy path) — this is the create-path behavior T-010 relies on;
   - **(e)** the existing `workspaces_select_tenant` still returns a row when `app.workspace_id` is set
     to that workspace (get-one path unchanged).
4. No change to existing grant set; no `FORCE ROW LEVEL SECURITY` in this task (defer to admin work,
   D-017 §3). No plaintext secrets/PII.
